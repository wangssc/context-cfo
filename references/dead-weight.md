# 死重判据

## 识别维度（三类，已实现）

### 1. 超长/主导文件

- **绝对超长**：单文件 token 中点 > 8000。对应一个臃肿正文，该拆到 references/ 按需加载。
- **主导文件**：单文件占总量 ≥ 30%。哪怕绝对 token 不高，它也是账单里最大的一块，值得优先看。

> 为什么用「主导文件」补充「绝对超长」：一个 20 文件目录里，单个 5000 token 的文件不算绝对超长，却占了总量的一半，它才是老板该先看的对象。绝对阈值单独用会漏掉这种「相对大头」。

### 2. 跨文件重复

两个不同文件共享 ≥ 40 字符的重复片段（滑动窗口大小 20 字符）。

- 实现：对每对文件取窗口集合交集，重复字符估计 = 交集窗口数 × 窗口大小。
- **已知高估**：窗口可能重叠，交集窗口数 × 窗口大小会**高估**真实重复字符数（比如一段 50 字符的重复，20 字符窗口会产生约 31 个重叠窗口，估成 620 字符）。这是下界之外的高估，已记录，不修正为「精确值」。

### 3. 触发条件模糊

SKILL.md 的 description < 20 字符。description 是唯一触发依据，过短意味着模型无法判断何时调用，该 skill 形同虚设，但删了又可能少能力——归为「中风险，需人工确认」。

## 未实现的维度（已知局限）

- **工具 schema 与描述重复**：mcp.json 里同名工具的 description 重复，未做。
- **同一规则跨三个文件重复**：目前只做两两配对，三文件及以上未做。
- **从没被触发词覆盖的段落**：需要语义分析，超出标准库范畴，未做。

## 风险分级

| 级别 | 判据 | 处置 |
|------|------|------|
| 低 | 背景叙述、重复规则 | 可删可压缩，损失小 |
| 中 | 触发条件模糊的 skill | 删了可能少能力，需人工确认 |
| 高 | 命中安全/合规关键词 | 不许删，只能压缩措辞 |

高风险的保守关键词：secret / key / token / credential / password / 安全 / 合规 / 密评 / 商用密码 / 身份 / 社保 / 工资 / 审计 / 红线。

## 盲区（必须标明，不推测）

不读使用日志，无法判断某个 skill 是否真的从未被使用。对「未使用」类对象只输出 `unknown`，**不输出「这个可能没人用」**——那是一种未经验证的推测。
